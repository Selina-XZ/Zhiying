# 知应

面向养老服务的数字人双向交流原型：老人可在明确打开麦克风后与魔珐数字人进行临时语音交流，也可上传症状原话、求助及其他内容；工作人员通过“事项与提醒、宣传讲解、自定义内容”三个入口下达信息；知应用数字人、大字、工作人员确认图片和渐进式大按钮帮助老人理解、选择并按需设置提醒。豆包只在服务端辅助生成图片，并生成语音对话的回答；不生成事项讲解。

未回应不算同意；确认收到不等于接受安排；选择或确认提醒也不等于事项已经完成。无真实外部业务接口时，系统只生成工作人员跟进记录，不声称已经办理。

## 运行

本项目只使用 Python 标准库、SQLite 和原生网页，无需安装第三方依赖。

```powershell
python server.py
```

浏览器访问 http://127.0.0.1:8765 。老人端数字人已经直接放在首页首屏，不需要打开独立业务页面。旧的 `/avatar-test.html?item=<编号>` 只保留为兼容入口，会自动返回 `/?item=<编号>`。

关闭服务使用 `Ctrl+C`。正式本地数据位于 `data/app.db`；页面刷新后数据保留。

## 工作人员发布三类内容

1. 切换到“工作人员端”。
2. 选择一个明显的功能卡：
   - **事项与提醒**：填写正文、时间、地点、可选图片、1～3 个业务选项，并决定是否允许提醒。
   - **宣传讲解**：只填写宣传正文和可选图片。
   - **自定义内容**：只填写自定义正文和可选图片。
3. 图片有三种路径：上传一张工作人员审核的 PNG、JPEG 或 WebP（最大 1.5 MiB）；主动请求豆包生成一张带 AI 水印的辅助图；或不选图片，使用“知应根据事项文字生成的信息图”兜底。人工图和豆包图都只在点击“确认提交”后与事项同事务保存；自动信息图不是大模型或文生图结果。
4. 只有“事项与提醒”需要为 1～3 个大按钮填写文案和含义。宣传讲解与自定义内容使用固定明确回应，不配置时间、地点、选项或提醒。
5. 在预览中核对原始正文、图片来源、时间、地点和选项，点击“确认提交”。豆包图片生成成功不等于发布成功，只有服务保存成功后页面才报告成功。

工作人员端顶部还有“老人端数字人运行状况”：分别显示老人页面是否在前台、SDK 会话是否连接、SDK 是否报告 `rendering`、当前是否播报、麦克风／ASR 是否正在聆听、当前事项、最近动作，以及 SDK 宿主尺寸、Canvas 和其他渲染节点的受限几何摘要。`rendering` 只表示 SDK 已报告渲染启动，背景或声音单独出现都不等于人物已经可见；状态只存服务进程内存，不写 SQLite，页面状态失效后显示“老人端当前未在线”。提醒的真实边界也集中放在该区域，不再增加老人端的信息负担。

### 可选：配置豆包辅助配图

豆包只在服务端调用 Seedream 图片接口和文本对话接口。API Key 不得发送到聊天、写入源码、`.env`、数据库、日志或浏览器存储；只在启动服务的同一个 PowerShell 进程中临时设置：

```powershell
$env:ARK_API_KEY='仅在本机终端输入'
$env:ARK_IMAGE_MODEL='doubao-seedream-5-0-flash-260915'
$env:ARK_TEXT_MODEL='doubao-seed-2-1-lite-260915'
python server.py
```

工作人员必须先填写虚构事实，再点击“生成辅助图片”。正文、时间或地点改变后旧生成图失效；人工上传图片与豆包图二选一。页面只在工作人员预览、核对并确认发布后保存图片。未配置、生成失败或图片不准确时，仍可使用人工上传或自动信息图，不会伪装成豆包成功。

## 老人使用

老人进入首页后先看到数字人主舞台；“我想告诉工作人员”和“我的事项与反馈”紧随其后。

### 上传内容

老人端先从三张大卡片中选择“身体不舒服、请工作人员帮忙、其他事情”，再填写和预览。症状内容按原话转交，不自动诊断，也不提供用药建议；代办提交只表示工作人员收到待处理内容。工作人员端可在对应事项卡内直接展开并保存回复，不再使用浏览器弹窗；回复只表示已反馈，不表示求助、代办或其他事项已经完成。

### 听懂并回应下达内容

1. 首页数字人先显示一条具体的手工花灯活动演示；演示内容不会写入数据库。
2. 在“我的事项与反馈”中点击“请知应告诉我”，事项会在当前页数字人舞台加载并自动滚回，不产生页面跳转。
3. 正式事项加载后，知应在真实会话和画面都可用时自动播报；播报中只显示按句分行的事项、必要的时间地点和大字字幕。
4. 播报结束或被停止后，才显示工作人员审核图片（或根据事项文字生成的信息图）和“重新听、我要回应、没听懂或需要帮助”。图片和选择位于舞台外，不会遮挡字幕。
5. 如果数字人未连接、画面没有确认或播报失败，页面如实显示大字并提供“先查看图片和选择”；技术问题不会阻断老人回应。
6. 点击“我要回应”后，才显示工作人员配置的 1～3 个大按钮；稍后决定、拒绝和请求工作人员放在二级“其他选择”中。
7. 再次核对选择并确认。只有后端保存成功后才显示正式状态。

桌面端舞台为 16:9 横屏。页面使用独立外层固定舞台尺寸，魔珐 SDK 只操作内部专用宿主；即使 SDK 写入 `position:relative; overflow:hidden`，也不会再覆盖外层的绝对定位并令宿主高度收缩。首次真实画面复测不传自定义 `config.layout`，也不调用 `changeLayout()`，由 SDK／角色资源使用默认构图。同步口型只用于辅助理解，不代表准确读唇。

页面主题使用低饱和的奶油白、燕麦、杏桃、陶土、暖棕和炭灰。舞台由浅奶油色平缓过渡到柔和陶土色；主要操作使用陶土或暖棕，警告和错误使用赭棕或陶土红。项目界面不使用紫色、绿色、荧光黄或高饱和粉，正文、按钮文字、边框和焦点环保持清楚对比。

## Agent 提醒如何工作

提醒是 SQLite 中的真实任务，而不是聊天承诺：

1. 工作人员启用提醒并填写事项时间。
2. 老人先保存一个标记为“选择后可设置提醒”的选项。
3. 老人选择有效的提前时间或自选时间；`POST /api/reminders` 插入成功后，页面才显示提醒编号和准确时间。
4. 服务内的提醒线程主动推进 `scheduled → due → presented` 状态。
5. 页面打开时每 10 秒领取一次到期或逾期提醒；真实数字人已连接时调用数字人播报，否则只显示醒目的大字提醒并如实说明未执行语音。
6. 老人可选择“我看到了、十分钟后再提醒、请工作人员帮助”。无人回应只有限重试；未确认展示或超过重试次数后进入逾期，并生成一次工作人员跟进记录。

### 提醒边界

- 页面关闭或设备休眠时，网页不能弹出或发声；它不是操作系统级闹钟。
- 服务停止时不能即时推进任务；重启后会补算到期状态。
- 到期但页面未打开时，不记录为“已经提醒”，而记录为“尚未确认展示／逾期”；下次打开补显。
- 工作人员跟进记录只表示需要实际跟进，不表示已经提供帮助。
- 当前原型没有身份认证，不能用于多位真实老人隔离或公开部署。

## 本机连接魔珐数字人

首页底部有折叠的“仅本机测试人员”设置。只有在 `127.0.0.1`／`localhost` 页面主动输入 App ID、App Secret 并勾选风险确认后，才动态加载魔珐 SDK。

1. 启动服务，打开 http://127.0.0.1:8765 。
2. 在首页底部展开“仅本机测试人员：连接或断开真实数字人”。
3. 从魔珐控制台复制当前驱动应用的 App ID 和 App Secret，只粘贴到本地页面，不要发送到聊天或截图中。
4. 勾选风险确认并点击“连接”；等待资源加载达到 100%。
5. 页面会先显示“会话已连接，等待 SDK 渲染”。收到 SDK 回调 `onRenderChange('rendering')` 后，页面只会提示“SDK 已报告渲染，人物待确认”；请实际查看背景和吴佳人物是否同时可见。仅有声音、背景或回调都不能称为人物画面已通过。
6. 使用“知应讲给我听”验证播报；播报中使用“停止播报”验证打断。工作人员端可同时查看会话、画面和播报状态。
7. 测试结束后展开设置并点击“断开数字人”，再关闭页面。

构造 SDK 时只传入专用的非零尺寸 DOM 宿主、会话凭据、网关和回调，不传自定义 `config.layout`。当前 SDK 源码会把宿主改为 `position:relative; overflow:hidden`，因此页面用独立外层维持 16:9 尺寸、让内部宿主始终 `width:100%; height:100%`。工作人员端会显示宿主、Canvas、video 和直接子节点的尺寸与显隐摘要，但不读取像素、文本、URL 或凭据。只有人物真实出现后，才考虑单独恢复自定义取景。

凭据只进入当前页面内存和魔珐 SDK；代码不写入源码、`.env`、数据库、日志、Cookie、`localStorage` 或 `sessionStorage`。但浏览器运行期间仍能检查到凭据，因此禁止公开部署。

语音交流由三部分协作完成：浏览器自带 `SpeechRecognition` 把老人语音转成文字，服务端豆包以“知应”人设生成短句回答，魔珐数字人用 `speak()` 合成声音与口型；魔珐 Brain 不参与问答，也不再回答“我是豆包”。点击一次“开始语音交流”后即进入连续对话，每句回答播报结束后自动继续聆听，点“结束语音交流”才关闭麦克风；数字人播报回答期间麦克风保持开启，老人可以直接开口打断它，识别器会把数字人自己的声音作为回声过滤掉，减少自我循环（建议用耳机／耳麦测试打断，效果更干净）。麦克风只在老人明确点击、老人页面在前台时开启；切换工作人员端、页面进入后台、断开或关闭时停止。语音转写文字会发送到服务端豆包，本项目不保存录音、识别文本、回答或对话，也不写入 SQLite、运行状态 API、浏览器存储或日志，不构成同意、业务提交或事项完成。当前不启用方言学习或声音克隆。

当前自动化验证了后端运行状态白名单、渲染节点摘要限制、提醒状态机和图片上传等本地逻辑；JavaScript 语法检查覆盖 SDK 适配器的默认初始化、宿主尺寸保护、播报、打断和销毁路径。这些检查不等同于真实 SDK 的人物画面。真实角色“吴佳”的实际画面、声音、口型、动作和打断仍需用户用自己的凭据验证；未验证前不称为真实数字人接入成功。

## API

- `GET /api/items`：读取全部事项、选项、回应事件和提醒摘要。
- `GET /api/items/<id>`：读取单条事项完整状态。
- `POST /api/items`：创建上传或下达内容；工作人员下达时可携带一张经过类型、大小和文件头校验的图片。
- `GET /api/items/<id>/image`：读取某条下达事项已保存的工作人员审核图片；事项 JSON 只返回图片 URL 和元信息，不返回 BLOB。
- `POST /api/respond`：保存老人通用选择、旧事项回应或工作人员反馈。
- `POST /api/reminders`：在满足前置条件后创建提醒。
- `POST /api/reminders/claim`：页面领取到期/逾期提醒并记录实际展示。
- `POST /api/reminders/respond`：确认、延后或请求人工。
- `POST /api/avatar-runtime`：老人页面上报不含凭据的会话、画面、播报、语音识别和当前事项状态；只存服务内存，不接收识别文本、回答或录音。
- `GET /api/avatar-runtime`：工作人员读取最新老人端状态；页面状态失效后显示未在线。
- `GET /api/ai/status`：只返回豆包图片与对话能力是否就绪和模型 ID，不返回 Key。
- `POST /api/ai/image`：由服务端按工作人员虚构正文调用豆包 Seedream 生成一张带水印图片；只返回待确认预览，不自动发布。
- `POST /api/voice/chat`：接受老人语音转写文字，由服务端豆包以“知应”人设生成回答；只返回回答，不落库、不返回 Key 或提示词。

## 自动化测试

```powershell
python -m unittest discover -s tests -v
```

测试覆盖旧数据库增量迁移、三类差异化发布、图片来源与确认后同事务保存、越权输入、回应历史、提醒前置条件、到期、实际展示、有限重试、逾期交接、延后、确认、请求帮助，以及数字人运行状态白名单与语音识别状态枚举、页面状态失效、多页面优先级、Canvas 与渲染节点几何摘要的数量／长度限制。豆包模块使用假 HTTP 覆盖当前 Seedream 请求、鉴权脱敏、非法图片、超限和并发保护。还覆盖 PNG/JPEG/WebP 上传、文件头与 MIME 校验、超限拒绝、图片 BLOB 不泄露到事项列表和无上传时的自动信息图标记。时间状态机使用固定时钟，所有测试使用临时 SQLite，不向 `data/app.db` 写入测试记录。

## 尚未实现或仍需验证

- 真实魔珐凭据下的“吴佳”初始化、实际口型、声音、动作与打断。
- 身份认证、不同老人数据隔离、公开部署和操作系统级后台通知。
- 魔珐端到端的记忆、知识库、Workflow 与业务工具调用：需要用户在魔珐控制台和真实业务授权下配置，当前原型不接真实老人数据。
- 症状原话之外的独立整理字段与人工核对流程。
- 经逐次授权的乡音词句、目标方言识别/合成和声音克隆。
- 工作人员图片的实际人工审核流程、恶意内容扫描和多租户访问控制。当前原型只限制上传格式和大小，尚无身份认证，不能用于公开部署。
